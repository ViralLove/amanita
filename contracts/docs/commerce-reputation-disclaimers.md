# Commerce reputation — disclaimers & UX copy (AMN-2.3 / AMN-2.6)

## Протокол не верифицирует внешние платежи

- **AmanitaCoin / LoveCoin** — доказуемые on-chain переводы в контур checkout (частичное funding по заказу).
- **Пара declare / accept** (AMN-2.2) — согласие сторон о полной оплате по **всем** согласованным рельсам; это **не** proof-of-funds для фиата/PSP.
- **Сигналы AMN-2.6** (`confirmOrderReceived`, `signalWeakExternalPaymentClaim`) — **добровольные** операционные метки для репутации; **не** доказательство доставки, **не** подтверждение банка/PSP.

## Метрики — не приговор

- Проценты в адаптере (`getBuyerReceivedWithoutDeclareBps`, `getSellerUnsettledAfterDeclareBps`) отражают **сигнальную дисциплину** в рамках смоделированных знаменателей, а не «плохой плательщик» / «мошенник».
- **Нет штрафных таймеров** за скорость оплаты или за отсутствие слабых сигналов.
- Sybil / сговор парой аккаунтов полностью не устраняются on-chain; вес «мягких» метрик должен быть ниже каноничных attestation-событий AMN-2.2.

## Рекомендуемый UI-копирайт (кратко)

| Действие | Подсказка пользователю |
|----------|-------------------------|
| `declareFullPayment` | «Подтверждаю полную оплату по договорённым способам (включая внешний перевод, если был).» |
| `acceptFullPayment` | «Принимаю подтверждение покупателя о полной оплате.» |
| `confirmOrderReceived` | «Добровольно отмечаю получение заказа — это помогает репутации и **не заменяет** спор/доставку.» |
| `signalWeakExternalPaymentClaim` | «Опционально: отмечаю, что внешний платёж отправлен — **не** означает оплаченность в протоколе.» |

## Канон «получен заказ» (on-chain)

- Событие **`OrderReceivedByBuyer`** эмитится при успешном `confirmOrderReceived` в статусе **`Paid`**.
- Учёт в адаптере для buyer-метрик срабатывает при **`markOrderSettled`**, если до settle был вызван `confirmOrderReceived` (флаг `buyerConfirmedReceivedBeforeSettle` в хуке).
