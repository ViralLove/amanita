# AI Journal: Анализ и план реализации метода очистки каталога

## 📋 Обзор задачи

**Цель:** Добавить в контракт `ProductRegistry.sol` метод для полной очистки каталога продавца с возможностью расширения функциональности.

**Контекст:** В каталог было загружено много тестовых данных, что создает необходимость в инструменте массовой очистки для управления каталогом.

## 🔍 Глубокий анализ существующей архитектуры

### 1. Структура данных контракта

**Основные хранилища:**
```solidity
mapping(uint256 => Product) private products;                    // Основное хранилище продуктов
mapping(address => uint256[]) private productsBySeller;          // Индекс по продавцам
uint256[] private activeProductIds;                              // Список активных продуктов
mapping(address => uint256) public catalogVersion;               // Версии каталогов
uint256 private _productIdCounter;                               // Счетчик ID продуктов
```

**Структура Product:**
```solidity
struct Product {
    uint256 id;          // Уникальный идентификатор
    address seller;      // Адрес продавца
    string ipfsCID;      // CID метаданных в IPFS
    bool active;         // Статус активности
}
```

### 2. Существующие методы управления

**Создание и обновление:**
- `createProduct(string calldata ipfsCID)` - создание продукта (неактивного)
- `updateProduct(uint256, string, uint256)` - обновление продукта
- `activateProduct(uint256)` - активация продукта
- `deactivateProduct(uint256)` - деактивация продукта

**Чтение данных:**
- `getProduct(uint256)` - получение продукта по ID
- `getProductsBySeller(address)` - получение всех продуктов продавца
- `getAllActiveProductIds()` - получение всех активных продуктов
- `getProductsBySellerFull()` - полная информация о продуктах продавца

### 3. Система безопасности

**Модификаторы доступа:**
- `onlyActivatedUser()` - проверка активации пользователя через InviteNFT
- `onlyOwnSellerProduct(uint256)` - проверка владения продуктом

**Проверки безопасности:**
- Все операции требуют активации в InviteNFT
- Продавцы могут управлять только своими продуктами
- Проверка существования продуктов перед операциями

## ⚠️ Анализ рисков и требований

### 1. Критические риски

**Безопасность:**
- **Неавторизованная очистка** - только владелец каталога должен иметь доступ
- **Потеря данных** - операция необратима, нужны дополнительные проверки
- **Нарушение целостности** - очистка должна корректно обновлять все индексы

**Производительность:**
- **Газовые лимиты** - массовая очистка может превысить лимит блока
- **Время выполнения** - операции с большими массивами могут быть медленными
- **Стоимость** - очистка большого количества продуктов может быть дорогой

### 2. Функциональные требования

**Основная функциональность:**
- Полная очистка каталога продавца
- Корректное обновление всех индексов
- Эмиссия событий для отслеживания
- Обновление версии каталога

**Расширяемость:**
- Возможность выборочной очистки (по статусу, дате, категории)
- Пакетная обработка для больших каталогов
- Возможность отката операций

## 📝 Детальный план реализации

### Этап 1: Базовая реализация

**Функция:** `clearSellerCatalog(address seller)`

**Логика:**
```solidity
function clearSellerCatalog(address seller) external {
    // 1. Проверка доступа
    require(inviteNFT.isSeller(msg.sender), "Not a seller");
    require(seller == msg.sender, "Can only clear own catalog");
    
    // 2. Получение списка продуктов
    uint256[] memory sellerProducts = productsBySeller[seller];
    uint256 productCount = sellerProducts.length;
    
    // 3. Очистка активных продуктов
    for (uint256 i = 0; i < productCount; i++) {
        uint256 productId = sellerProducts[i];
        Product storage product = products[productId];
        
        if (product.active) {
            // Удаление из activeProductIds
            _removeFromActiveProducts(productId);
        }
        
        // Удаление продукта
        delete products[productId];
    }
    
    // 4. Очистка индекса продавца
    delete productsBySeller[seller];
    
    // 5. Обновление версии
    catalogVersion[seller] += 1;
    
    // 6. Эмиссия события
    emit CatalogCleared(seller, productCount);
    emit CatalogUpdated(seller, catalogVersion[seller]);
}
```

### Этап 2: Вспомогательные функции

**Функция:** `_removeFromActiveProducts(uint256 productId)`

**Назначение:** Эффективное удаление продукта из списка активных

**Реализация:**
```solidity
function _removeFromActiveProducts(uint256 productId) private {
    uint256 len = activeProductIds.length;
    for (uint256 i = 0; i < len; i++) {
        if (activeProductIds[i] == productId) {
            activeProductIds[i] = activeProductIds[len - 1];
            activeProductIds.pop();
            break;
        }
    }
}
```

### Этап 3: События и логирование

**Новые события:**
```solidity

event ProductBatchCleared(address indexed seller, uint256[] productIds);
```

**Функция:** `clearSellerCatalogSelective(address seller, uint256[] memory productIds)`

**Назначение:** Выборочная очистка конкретных продуктов

**Функция:** `clearSellerCatalogByStatus(address seller, bool activeOnly)`

**Назначение:** Очистка только активных или неактивных продуктов
