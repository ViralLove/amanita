# Архитектура безопасности и децентрализации системы селлеров

## Концепция разделенных процессов активации и назначения ролей

### Основная идея
Система построена на принципе **разделения двух независимых процессов**:
1. **Активация пользователя** - делает адрес "живым" в системе (получает инвайты)
2. **Назначение роли SELLER_ROLE** - дает права на управление продуктами

Это позволяет создать гибкую систему, где обычные пользователи и селлеры проходят одинаковый процесс активации, но получают разные права в зависимости от назначения ролей.

## Архитектура системы

### Роли и их функции

#### 1. **DEFAULT_ADMIN_ROLE (Деплоер-Бог)**
- **Функции**: Управление системой, создание первого селлера, назначение ролей
- **Процесс активации**: Создает системный аккаунт и активирует первого селлера
- **Процесс назначения**: Может назначать любые роли любому пользователю
- **Ответственность**: Запуск экосистемы, общее управление

#### 2. **ACTIVATOR_ROLE (Активаторы)**
- **Функции**: Активация новых пользователей (любых, не только селлеров)
- **Процесс активации**: Активирует пользователей, которые получают инвайты
- **Процесс назначения**: Может назначать роль SELLER_ROLE по иерархической спирали
- **Ограничения**: Несут ответственность за качество активированных пользователей
- **Ответственность**: За качество активированных пользователей

#### 3. **SELLER_ROLE (Селлеры)**
- **Функции**: Управление продуктами, создание каталогов, продажа
- **Процесс активации**: Проходят обычную активацию как все пользователи
- **Процесс назначения**: Получают роль SELLER_ROLE от активатора
- **Ограничения**: Не могут активировать других (если не имеют ACTIVATOR_ROLE)
- **Ответственность**: Качество продукции, соблюдение стандартов

### Схема процессов

#### Процесс 1: Активация пользователей
```
Деплоер-Бог (ADMIN_ROLE)
    ↓ создает и активирует
Первый Селлер (ACTIVATOR_ROLE)
    ↓ активирует пользователей
Любые пользователи (получают инвайты)
    ↓ могут быть активированы
Новые пользователи (получают инвайты)
```

#### Процесс 2: Назначение роли SELLER_ROLE
```
Деплоер-Бог (ADMIN_ROLE)
    ↓ назначает роль
Первый Селлер (SELLER_ROLE + ACTIVATOR_ROLE)
    ↓ назначает роль по спирали
Второй Селлер (SELLER_ROLE)
    ↓ может назначить роль
Третий Селлер (SELLER_ROLE)
```

#### Комбинированная схема
```
👑 Деплоер создает первого селлера:
   1. Создает адрес
   2. Активирует пользователя
   3. Назначает SELLER_ROLE
   4. Назначает ACTIVATOR_ROLE

🌱 Первый селлер может:
   1. Активировать пользователей (ACTIVATOR_ROLE)
   2. Назначать SELLER_ROLE по спирали

👤 Обычный пользователь:
   1. Активируется любым активатором
   2. Получает 12 инвайт-кодов
   3. НЕ получает SELLER_ROLE (только покупает)

🍄 Новый селлер:
   1. Активируется как обычный пользователь
   2. Получает 12 инвайт-кодов
   3. Получает SELLER_ROLE от активатора
   4. Может получить ACTIVATOR_ROLE (если доверяют)
```

## Система ответственности и санкций

### Принцип каскадной ответственности

#### Отслеживание ответственности:
- **userActivator[address]** - кто активировал пользователя
- **sellerNominator[address]** - кто назначил роль SELLER_ROLE
- **activatedUsers[address]** - список пользователей, активированных данным активатором
- **nominatedSellers[address]** - список селлеров, назначенных данным номинатором

#### Санкции при нарушениях:

**Если нарушает обычный пользователь:**
1. **Немедленные санкции**:
   - Заморозка аккаунта нарушителя
   - Изъятие всех инвайт-кодов
   - Запрет на получение новых инвайтов

2. **Санкции для активатора**:
   - **Первое нарушение**: Предупреждение + запись в журнал
   - **Второе нарушение**: Временная приостановка прав активатора (7 дней)
   - **Третье нарушение**: Лишение роли ACTIVATOR_ROLE на 30 дней

**Если нарушает селлер:**
1. **Немедленные санкции**:
   - Заморозка аккаунта нарушителя
   - Блокировка всех его продуктов
   - Изъятие всех инвайт-кодов
   - Лишение роли SELLER_ROLE

2. **Санкции для номинатора** (кто назначил роль SELLER_ROLE):
   - **Первое нарушение**: Предупреждение + временная приостановка прав номинатора (7 дней)
   - **Второе нарушение**: Лишение права назначать SELLER_ROLE на 30 дней
   - **Третье нарушение**: Постоянное лишение права назначать SELLER_ROLE

3. **Каскадный эффект**:
   - Все селлеры, назначенные нарушителем, переходят под контроль номинатора нарушителя
   - Если номинатор нарушителя также лишается прав, селлеры переходят к следующему уровню вверх

### Матрица ответственности

| Тип нарушителя | Уровень нарушения | Санкции для нарушителя | Санкции для активатора | Санкции для номинатора | Действия с сетью |
|----------------|-------------------|----------------------|----------------------|----------------------|------------------|
| Обычный пользователь | Мелкое нарушение | Предупреждение | Запись в журнал | - | Мониторинг |
| Обычный пользователь | Серьезное нарушение | Временная блокировка | Предупреждение | - | Контроль активатора |
| Обычный пользователь | Критическое нарушение | Постоянная блокировка | Лишение ACTIVATOR_ROLE | - | Передача активированных |
| Селлер | Мелкое нарушение | Предупреждение | - | Запись в журнал | Мониторинг |
| Селлер | Серьезное нарушение | Временная блокировка + лишение SELLER_ROLE | - | Предупреждение | Передача селлеров |
| Селлер | Критическое нарушение | Постоянная блокировка + лишение SELLER_ROLE | - | Лишение права назначать | Каскадная передача |
| Селлер | Злоумышленничество | Полное исключение | - | Жесткие санкции | Реструктуризация сети |

## Живой пример: Экосистема "Amanita Marketplace"

### Сценарий 1: Нормальное развитие

#### Этап 1: Запуск системы
```
👑 Деплоер-Бог (0xAdmin...)
    ↓ создает адрес и активирует
🌱 Анна (0xAnna...) - Первый селлер
    ✅ Активирована как пользователь
    ✅ Назначена роль SELLER_ROLE
    ✅ Назначена роль ACTIVATOR_ROLE
```

**Результат**: Анна получает 12 инвайт-кодов, может управлять продуктами и активировать других пользователей.

#### Этап 2: Рост сети
```
👑 Деплоер-Бог (0xAdmin...)
    ↓
🌱 Анна (0xAnna...) - Активатор + Селлер
    ↓ активирует Бориса
👤 Борис (0xBoris...) - Активированный пользователь
    ↓ Анна назначает роль SELLER_ROLE
🍄 Борис (0xBoris...) - Новый селлер (под ответственностью Анны)
    ↓ Борис активирует Викторию
👤 Виктория (0xVictoria...) - Активированная пользователь
    ↓ Борис назначает роль SELLER_ROLE
🌿 Виктория (0xVictoria...) - Еще один селлер (под ответственностью Бориса)
```

**Результат**: Создается цепочка доверия, где каждый несет ответственность за своих рефералов. Анна отвечает за Бориса, Борис отвечает за Викторию.

### Сценарий 2: Обнаружение нарушения

#### Ситуация: Борис продает некачественную продукцию

```
👑 Деплоер-Бог (0xAdmin...)
    ↓
🌱 Анна (0xAnna...) - Активатор Бориса
    ↓ активировала
❌ Борис (0xBoris...) - НАРУШИТЕЛЬ
    ↓ активировал
🌿 Виктория (0xVictoria...) - Под угрозой
```

#### Действия системы:

1. **Обнаружение нарушения**:
   - Покупатели жалуются на продукцию Бориса
   - Система автоматически замораживает аккаунт Бориса
   - Все продукты Бориса скрываются из каталога

2. **Санкции для Анны (активатора)**:
   - Получает предупреждение
   - Лишается права активации на 7 дней
   - Обязана контролировать Викторию

3. **Судьба Виктории**:
   - Переходит под прямой контроль Анны
   - Анна несет ответственность за качество продукции Виктории
   - Если Виктория также нарушает правила, Анна получает более серьезные санкции

### Сценарий 3: Каскадное нарушение

#### Ситуация: Анна также нарушает правила

```
👑 Деплоер-Бог (0xAdmin...)
    ↓
❌ Анна (0xAnna...) - АКТИВАТОР-НАРУШИТЕЛЬ
    ↓ активировала
❌ Борис (0xBoris...) - УЖЕ ЗАБЛОКИРОВАН
    ↓ активировал
🌿 Виктория (0xVictoria...) - Нуждается в новом активаторе
```

#### Действия системы:

1. **Санкции для Анны**:
   - Лишение роли ACTIVATOR_ROLE на 30 дней
   - Заморозка всех продуктов
   - Передача всех ее селлеров под контроль Деплоера-Бога

2. **Реструктуризация сети**:
   - Виктория переходит под прямой контроль Деплоера-Бога
   - Деплоер-Бог может назначить нового активатора для Виктории
   - Создается новая ветка сети

### Сценарий 4: Восстановление после нарушений

#### Ситуация: Анна исправляется

```
👑 Деплоер-Бог (0xAdmin...)
    ↓
🌱 Анна (0xAnna...) - ВОССТАНОВЛЕНА
    ↓ снова может активировать
🌿 Виктория (0xVictoria...) - Под контролем Анны
```

#### Процесс восстановления:

1. **Период реабилитации** (30 дней):
   - Анна не может активировать новых селлеров
   - Должна доказать свою надежность
   - Контролирует качество продукции Виктории

2. **Восстановление прав**:
   - После успешного прохождения реабилитации
   - Анна снова получает роль ACTIVATOR_ROLE
   - Может активировать новых селлеров

## Техническая реализация

### Контракт InviteNFT.sol

```solidity
// Роли
bytes32 public constant DEFAULT_ADMIN_ROLE = keccak256("DEFAULT_ADMIN_ROLE");
bytes32 public constant ACTIVATOR_ROLE = keccak256("ACTIVATOR_ROLE");
bytes32 public constant SELLER_ROLE = keccak256("SELLER_ROLE");

// Отслеживание активаций
mapping(address => address) public activatorOf; // кто активировал кого
mapping(address => address[]) public activatedBy; // кого активировал кто

// Санкции
mapping(address => uint256) public violationCount; // счетчик нарушений
mapping(address => uint256) public suspensionUntil; // до какого времени заблокирован

function activateAndMintInvites(
    string memory inviteCode,
    address user,
    string[] memory newInviteCodes,
    uint256 expiry
) external onlyRole(ACTIVATOR_ROLE) {
    // Записываем кто кого активировал
    activatorOf[user] = msg.sender;
    activatedBy[msg.sender].push(user);
    
    // ... остальная логика активации
}

function suspendUser(address user, uint256 duration) external onlyRole(DEFAULT_ADMIN_ROLE) {
    suspensionUntil[user] = block.timestamp + duration;
    violationCount[user]++;
    
    // Каскадные санкции для активатора
    address activator = activatorOf[user];
    if (activator != address(0)) {
        _applyActivatorSanctions(activator, violationCount[user]);
    }
}
```

### Скрипт мониторинга

```javascript
// Функция для применения санкций
async function applySanctions(violatorAddress, violationType) {
    const inviteNFT = await loadContract("InviteNFT");
    
    // 1. Замораживаем нарушителя
    await inviteNFT.methods.suspendUser(violatorAddress, getSuspensionDuration(violationType)).send({
        from: deployerAccount.address,
        gas: 500000
    });
    
    // 2. Получаем активатора
    const activator = await inviteNFT.methods.activatorOf(violatorAddress).call();
    
    // 3. Применяем санкции к активатору
    if (activator !== "0x0000000000000000000000000000000000000000") {
        await applyActivatorSanctions(inviteNFT, activator, violationType);
    }
    
    // 4. Перераспределяем селлеров нарушителя
    await redistributeSellers(inviteNFT, violatorAddress, activator);
}
```

## Преимущества системы

### 1. **Безопасность через социальный граф**
- Каждый активатор заинтересован в качественных рефералах
- Естественная фильтрация нежелательных участников
- Сложность для злоумышленников проникнуть в систему

### 2. **Децентрализация с контролем**
- Власть распределена между активаторами
- Деплоер-Бог контролирует только критические функции
- Система саморегулируется через ответственность

### 3. **Масштабируемость**
- Сеть может расти экспоненциально
- Каждый новый активатор расширяет возможности системы
- Автоматическое перераспределение при нарушениях

### 4. **Устойчивость к атакам**
- Сложно атаковать всю сеть одновременно
- Нарушения изолируются и не распространяются
- Быстрое восстановление после инцидентов

## Заключение

Иерархическая спираль активации с каскадной ответственностью создает устойчивую, безопасную и децентрализованную экосистему. Система саморегулируется через экономические и социальные стимулы, обеспечивая высокое качество участников и продукции.
