- **Чёткий источник шагов** — раздел P1 отчёта квалификации однозначно задаёт четыре замечания с рекомендациями; не пришлось интерпретировать формулировки.  
- **Проверка уже сделанного** — P1.1, P1.2, P1.4 были реализованы в предыдущем ответе; run-phase заставил явно провалидировать их (grep/тесты) и зафиксировать в ретроспективе.  
- **Явное решение по опциональному шагу** — P1.3 помечен «опционально»; по методике зафиксировано «выполняем» и добавлен тест; один новый тест, 39 всего.  
- **Обновление отчёта** — в отчёте квалификации проставлены «Выполнено» по пунктам 2–4 и обновлена сводная таблица; следующий читатель видит закрытые замечания.

---

## Что сработало плохо или создало риски

- **Фаза «из отчёта», а не из solution-architecture** — шаги брались из списка замечаний P1, а не из таблицы «Фаза N» архитектурного документа. Методика run-phase предполагает документ с фазой и таблицей шагов; здесь фаза была неявной (отработка замечаний). Риск небольшой: замечания нумерованы и рекомендации чёткие.  
- **Ретроспектива по продукту ссылается на «план»** — план здесь = формулировки из отчёта квалификации (строки 41–70); в ретроспективе цитируются кратко «задано по плану» по каждому пункту. Соответствует духу методики (источник истины — документ).

## Уроки для следующих фаз

- Отработку замечаний из отчёта квалификации можно оформлять как фазу с шагами P1.1–P1.K; run-phase применим, если вынести замечания в TODO и выполнять по одному с валидацией.  
- Опциональный шаг — явно «выполняем» или «пропускаем, причина»; в ретроспективе по продукту указать статус и комментарий.  
- После отработки замечаний обновлять сам отчёт (Выполнено, сводная таблица), чтобы не оставалось впечатления незакрытых пунктов.
