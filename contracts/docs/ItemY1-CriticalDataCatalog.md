# ItemY1.2: Документирование критических данных SpiralEngine

## 📊 Обзор критических данных

SpiralEngine содержит критически важные данные для функционирования спиральной экономики AMANITA. Все данные разделены на 4 основные категории по важности и типу.

## 🎯 Категоризация критических данных

### 1. Социальный капитал (Social Capital) - КРИТИЧЕСКИ ВАЖНО

**Описание:** Данные, формирующие спиральную иерархию и социальные связи между пользователями.

#### 1.1 Спиральная иерархия
```solidity
// Кто активировал пользователя - основа спиральной структуры
mapping(address => address) public userActivator;

// Кого активировал данный активатор - формирование кругов
mapping(address => address[]) public activatedBy;

// Кто назначил роль SELLER_ROLE - цепочка ответственности
mapping(address => address) public sellerNominator;

// Кого назначил селлером данный номинатор - отслеживание номинаций
mapping(address => address[]) public nominatedSellers;
```

**Критичность:** 🔴 МАКСИМАЛЬНАЯ  
**Причина:** Основа спиральной экономики, потеря = разрушение всей социальной структуры

#### 1.2 Статус активации
```solidity
// Массив всех активированных пользователей
address[] public activatedUsers;

// Использованный инвайт пользователя
mapping(address => uint256) public usedInviteByUser;
```

**Критичность:** 🔴 МАКСИМАЛЬНАЯ  
**Причина:** Определяет права доступа к системе, потеря = блокировка всех пользователей

### 2. Экономические активы (Economic Assets) - КРИТИЧЕСКИ ВАЖНО

**Описание:** Инвайты как ограниченный ресурс и основа экономической модели.

#### 2.1 Инвайт-коды и токены
```solidity
// Маппинг: inviteCode => tokenId - уникальные коды инвайтов
mapping(string => uint256) public inviteCodeToTokenId;

// Маппинг: inviteCode => существует ли код
mapping(string => bool) public inviteCodeExists;

// Маппинг: tokenId => inviteCode
mapping(uint256 => string) public tokenIdToInviteCode;

// Маппинг: tokenId => использован ли инвайт
mapping(uint256 => bool) public isInviteUsed;
```

**Критичность:** 🔴 МАКСИМАЛЬНАЯ  
**Причина:** Инвайты = ограниченный ресурс = ценность, потеря = экономический коллапс

#### 2.2 Инвайт-метаданные
```solidity
// Срок действия инвайта
mapping(uint256 => uint256) public inviteExpiry;

// Дата создания инвайта
mapping(uint256 => uint256) public inviteCreatedAt;

// Адрес создателя инвайта
mapping(uint256 => address) public inviteMinter;

// Адрес первого владельца инвайта
mapping(uint256 => address) public inviteFirstOwner;

// История владельцев инвайта
mapping(uint256 => address[]) public inviteTransferHistory;
```

**Критичность:** 🟡 ВЫСОКАЯ  
**Причина:** Важно для отслеживания и аудита, но не блокирует основную функциональность

#### 2.3 Счетчики и статистика
```solidity
// Общее количество использованных инвайтов
uint256 public totalInvitesUsed;

// Общее количество выданных инвайтов
uint256 public totalInvitesMinted;

// Количество инвайтов пользователя
mapping(address => uint256) public userInviteCount;

// Список инвайтов пользователя (private)
mapping(address => uint256[]) private userInvites;
```

**Критичность:** 🟡 ВЫСОКАЯ  
**Причина:** Важно для аналитики и ограничений, но можно восстановить из других данных

### 3. Репутационная система (Reputation System) - ВЫСОКАЯ ВАЖНОСТЬ

**Описание:** Система санкций и ответственности, обеспечивающая качество спиральной экономики.

#### 3.1 Нарушения пользователей
```solidity
// Счетчик нарушений для каждого пользователя
mapping(address => uint256) public violationCount;

// До какого времени заблокирован пользователь
mapping(address => uint256) public suspensionUntil;
```

**Критичность:** 🟡 ВЫСОКАЯ  
**Причина:** Важно для поддержания качества, но не блокирует основную функциональность

#### 3.2 Ответственность активаторов и номинаторов
```solidity
// Нарушения активированных пользователей (для активатора)
mapping(address => uint256) public activationViolations;

// Нарушения назначенных селлеров (для номинатора)
mapping(address => uint256) public nominationViolations;
```

**Критичность:** 🟡 ВЫСОКАЯ  
**Причина:** Важно для каскадной ответственности, но можно восстановить

### 4. Интеграционные данные (Integration Data) - СРЕДНЯЯ ВАЖНОСТЬ

**Описание:** Данные для интеграции с другими компонентами экосистемы.

#### 4.1 SoulIdentity интеграция
```solidity
// Адрес контракта SoulIdentity для делегирования SBT функций
ISoulIdentity public soulIdentity;
```

**Критичность:** 🟠 СРЕДНЯЯ  
**Причина:** Можно переустановить, не блокирует основную функциональность

## 📋 Структуры данных

### InviteInfo
```solidity
struct InviteInfo {
    string inviteCode;           // Код инвайта
    uint256 tokenId;            // ID токена инвайта
    bool isUsed;                // Статус использования
    address activatedBy;        // Адрес активатора (если инвайт использован)
    uint256 activationTime;     // Время активации
    uint256 expiry;             // Срок действия
}
```

**Использование:** Диагностика инвайтов, полная информация об инвайте  
**Критичность:** 🟡 ВЫСОКАЯ

### SellerDiagnostics
```solidity
struct SellerDiagnostics {
    bool isActivated;           // Статус активации пользователя
    uint256 usedInviteTokenId;  // ID использованного инвайта
    bool hasSellerRole;         // Наличие роли SELLER_ROLE
    bool hasActivatorRole;      // Наличие роли ACTIVATOR_ROLE
    InviteInfo[] userInvites;   // Массив инвайтов пользователя
    uint256 totalInvitesMinted; // Общее количество заминченных инвайтов
}
```

**Использование:** Полная диагностика состояния селлера  
**Критичность:** 🟡 ВЫСОКАЯ

    // Проверка счетчиков

## ⚠️ Риски потери данных

### Критические риски
1. **Потеря спиральной иерархии** - разрушение всей экономической модели
2. **Потеря инвайт-кодов** - невозможность активации новых пользователей
3. **Потеря статуса активации** - блокировка всех пользователей

### Митигация рисков
1. **Полное резервное копирование** перед миграцией
2. **Поэтапная миграция** с проверкой на каждом этапе
3. **Rollback план** для отката к предыдущей версии
4. **Мониторинг** целостности данных в реальном времени
