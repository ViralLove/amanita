Отработка теста для смарт контракта
Проанализируй и исправь тесты в файле contracts/tests/***.test.js используя методологию @test-to-success.mdc.

Выполни следующие этапы:

1. **Первичный анализ и выявление ошибок**:
   - Запусти тесты: `npx hardhat test contracts/tests/***.test.js`
   - Проанализируй структуру тестов (количество describe/it блоков)
   - Выяви все ошибки и их типы

2. **Жёсткий анализ качества тестов (@test-qualification.mdc)**:
   - Проверь на ложные успехи (NO_FALSE_SUCCESSES)
   - Убедись в покрытии критических путей (NO_UNTESTED_CRITICAL_PATHS)
   - Проанализируй логику тестов (CORRECT_LOGIC)
   - Оцени использование моков (MINIMAL_MOCK_OVERUSE)

3. **Детальный анализ ошибок в журнале**:
   - Документируй каждую ошибку в contracts/docs/AIjournal.md
   - Классифицируй по типам: логические, технические, инфраструктурные
   - Выяви корневые причины

4. **Планирование исправлений**:
   - Создай acceptance criteria для каждого исправления
   - Приоритизируй по P0/P1/P2

5. **Последовательное исправление через @run-task.mdc**:
   - ItemY1: Исправление ложных успехов (P0)
   - ItemY2: Исправление логических ошибок (P1) 
   - ItemY3: Оптимизация использования моков (P2)

6. **Валидация результатов**:
   - Проверь каждый ItemY отдельно
   - Финальная проверка всех тестов
   - Убедись в 100% успешности

7. **Документирование**:
   - Обнови журнал с результатами
   - Создай коммит изменений

Критические пути для анализа в ***.test.js:
- Создание и управление кругами (getCircleSize, getCircleMembers)
- Ограничения кругов (лимит 12 участников)
- Иерархия и отношения (userActivator, activatedBy)
- Валидация принадлежности инвайтов (isInviteFromActivator)
- Статистика и мониторинг кругов
- Edge cases для кругов

Используй жёсткий анализ качества - не принимай успехи на веру, проверяй реальную функциональность!
