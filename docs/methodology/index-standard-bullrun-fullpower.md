## Стандарт тематических индексов задач (Index Standard — bullrun fullpower)

**Версия:** 1.0  
**Зона применения:** `*/docs/analysis/*-index.md` (тематические индексы тасков: tests, SBT, social-mining и т.д.)  
**Опора:** `task-standard.md`, `@.cursor/commands/run-analysis.md`

---

### 1. Назначение

Тематический индекс задач — это **живая карта задач по одной области**, которая:

- связывает таски с подсистемами (SBT, sanctions, UUPS, tests, social‑mining и т.д.);
- показывает **статус и приоритет** в одном экране;
- служит **точкой входа** для run-task / run-phase (какой таск продолжать, какой создавать).

Индекс **не дублирует постановки** задач, а агрегирует ссылки и метаданные.

---

### 2. Базовый формат индекса

Индекс — обычный markdown‑файл со следующей структурой:

1. **Заголовок и зона**
   - Название области (`SpiralEngine — Test Tasks Index`, `Social Mining — Tasks Index` и т.п.).
   - Краткая цель индекса (1–2 строки).
   - Ссылки на соседние/родительские индексы (SBT, social‑mining и т.д.).

2. **Секции по подсистемам**
   - Каждая секция = одна подсистема / тема (SBT, Sanctions, UUPS, Integration & Roles, infra‑tests, social‑mining и т.п.).
   - Внутри — **таблица задач** с фиксированными столбцами.

3. **Сводка по статусам и правила использования**
   - Краткая легенда статусов.
   - Как добавлять новые задачи и как читать индекс.

---

### 3. Табличный формат (Jira‑style) с цифровым кодированием и цветом

Каждая секция использует **единую таблицу**:

```markdown
### <Секция>

**Коды статусов:** ⚪ = 0 — Todo, 🟡 = 1 — In Progress, 🔵 = 2 — Implemented (Waiting Acceptance), 🟢 = 3 — Done (Awaiting Commits).

| S | Key | Task | Type | Status | Scope / Notes |
|---|-----|------|------|--------|---------------|
| 🟡 | SBT-1 | [task-fix-spiralengine-sbt-tests](./task-fix-spiralengine-sbt-tests.md) | fix | In Progress | Адаптация `SpiralEngine.sbt.test.js` под ethers v6 (bigint vs number), стабилизация базового SBT‑сьюта. |
```

**Столбцы:**

- **S** — **код статуса** (цифра + цветной кружок):
  - ⚪ = `0` — **Todo** (постановка есть, работа не начата);
  - 🟡 = `1` — **In Progress** (выполняются фазы 1–5 по run-task);
  - 🔵 = `2` — **Implemented (Waiting Acceptance)** (код написан, ждёт формальной приёмки/ревью);
  - 🟢 = `3` — **Done (Awaiting Commits)** (фазы 1–9 завершены: реализация, квалификация, верификация; коммиты и push отдельно).
- **Key** — короткий код задачи (namespace‑style):
  - `SBT-1`, `SAN-1`, `UUPS-1`, `INT-1`, `CORE-1` и т.п.;
  - формат: `<DOMAIN>-<NN>`, где DOMAIN = 3–5 заглавных букв подсистемы.
- **Task** — markdown‑ссылка на файл постановки таска (см. `task-standard.md`).
- **Type** — тип задачи (`fix`, `tests`, `implement`, `refactor`, `infra`, `data`).
- **Status** — текстовый статус (см. ниже).
- **Scope / Notes** — краткое описание области ответственности таска (1–2 предложения, без дублирования полного task‑дока).

---

### 4. Статусы и их связь с run-task

Статусы в индексе должны **отражать реальное положение таска в процессе run-task**:

- **Todo (S = 0)** — есть файл постановки, но фазы 1–5 ещё не запускались.
- **In Progress (S = 1)** — идут фазы:
  - 1: анализ и рамки;
  - 2: решения;
  - 3: архитектура;
  - 4: план реализации;
  - 5: реализация по фазам.
- **Implemented (Waiting Acceptance) (S = 2)** — фаза 5 завершена, код есть, но:
  - квалификация тестов (фаза 7) и принятие по AC (фаза 8) ещё не полностью оформлены, **или**
  - оформлены, но нужна формальная приёмка/ревью.
- **Done (Phase 1–9, Awaiting Commits) (S = 3)** — фазы 1–9 пройдены:
  - реализация, тесты, квалификация, верификация, документация;
  - коммиты и push выполняются отдельно (по git‑методике), поэтому статус подчёркивает, что задача завершена по предметной части, но ещё не закреплена в истории git.

В описательном блоке индекса (`Как пользоваться этим индексом`) обязательно кратко повторять эту легенду.

---

### 5. Правила ведения тематического индекса

1. **Один индекс — одна тема:**  
   Например: `tests-tasks-index.md` для SpiralEngine‑тестов; отдельный индекс для social‑mining, отдельный — для деплоя.

2. **Одна строка = один таск (One Task = One Gap):**  
   Соответствует принципу из `task-standard.md`: одна задача = один конкретный gap/issue. Если таск разрастается — декомпозировать и добавить несколько строк/файлов.

3. **Ссылки только на task‑файлы:**  
   В колонке `Task` — только постановки задач (task-*.md), а не worklog/CHANGELOG/analysis‑файлы.

4. **Не дублировать подробные описания:**  
   В `Scope / Notes` — только сжатое объяснение «о чём этот таск» + ключевые цифры (например, `33 passing`, `Phase 1–9 done`); детали — в самом таске.

5. **Синхронизация статусов:**  
   - При изменении статуса таска в его файле (`**Статус:** ...` + AC/DoD чекбоксы) — обновлять и строку в индексе.
   - Направление истины по содержанию — **сам таск**, индекс — агрегатор состояний.

6. **Кодирование статусов (кружок+цифра) — обязательное:**  
   Столбец `S` обязателен для всех таблиц, чтобы визуально (цвет) и программно (цифра) можно было:
   - быстро увидеть прогресс по подсистеме;
   - отфильтровать, например, все задачи с кодом `0` (Todo) или `1` (In Progress).

---

### 6. Пример: текущий tests-tasks-index.md (SpiralEngine)

Файл `contracts/docs/analysis/tasks/tests-tasks-index.md` оформлен по этому стандарту:

- Заголовок + зона + цели (строки 1–7).
- Секции 1–7 по подсистемам (SBT, sanctions, UUPS, integration, basic/circles, core‑infra Phase 1, core‑infra Phase 2).
- Каждая секция использует таблицу `S | Key | Task | Type | Status | Scope / Notes`.
- В секции 1 явно указана легенда `S` (0–3).
- В конце раздел `Как пользоваться этим индексом` с кратким описанием статусов и рекомендациями.

Этот индекс можно использовать как **референс‑пример** при создании других тематических индексов (SBT, social‑mining, deploy, bot‑tests и т.п.).

---

### 7. Требования к новым индексам

При создании нового тематического индекса:

- использовать тот же заголовочный блок (цель, зона, ссылки на соседние индексы);
- разбивать на секции по подсистемам/домейнам;
- использовать ровно те же столбцы таблиц и коды статусов;
- добавлять краткий раздел «Как пользоваться этим индексом» по аналогии с `tests-tasks-index.md`.
