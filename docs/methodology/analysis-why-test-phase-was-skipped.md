# Анализ: почему при работе по методике были пропущены задачи с тестами

**Дата:** 2026-01-30  
**Контекст:** task-batch-mint-invites; после Phase 1 (реализация кода) не была выполнена Phase 2 (тесты mintInviteBatch) и этап «Квалификация тестов».  
**Источники:** @docs/methodology/task-execution-process.md, @.cursor/commands/run-task.md, @.cursor/commands/run-analysis.md, @.cursor/commands/run-phase.md

---

## 1. Идентифицированные причины

### 1.1. «Одна фаза за раз» без явной связи со всеми фазами плана

**Где:** run-task.md, п. 1: «выполняй этапы процесса … по одному или по одному **блоку** (напр. **одна фаза за раз**)».

**Проблема:** Исполнитель сделал Phase 1 и остановился, ожидая фидбек. В solution-architecture фазы — 0, 1, **2 (тесты)**, 3. Phase 2 — это фаза с добавлением тестов. Не зафиксировано, что «реализация по фазам» = выполнение **всех** запланированных фаз по плану реализации и что **фаза с тестами не опциональна**.

**Итог:** Остановка после Phase 1 воспринимается как корректная («одна фаза за раз»), без проверки: «следующая фаза по плану — Phase 2 (тесты), её нельзя пропускать».

---

### 1.2. Разрыв между этапом 5 (фазы) и этапом 7 (квалификация тестов)

**Где:** task-execution-process.md, таблица этапов: 5 — «Реализация по фазам», 7 — «Квалификация тестов и отчёт».

**Проблема:** Квалификация (этап 7) применяется к «любому **созданному/изменённому** набору тестов». Но **создание** набора тестов в этом таске — это **Phase 2** внутри этапа 5. Если исполнитель выполнил только Phase 1 (код) и остановился, тестов ещё нет → этап 7 не срабатывает как напоминание «сначала добавь тесты». В процессе не сказано, что для тасков с новой функциональностью в плане **обязательно есть фаза тестов** и что этап 5 не считается завершённым, пока не выполнены все запланированные фазы, включая фазу с тестами.

**Итог:** Нет явной связи «Phase 2 = тесты → выполнить в рамках этапа 5 → затем этап 7».

---

### 1.3. В run-task этапы перечислены без раскрытия «фазы»

**Где:** run-task.md: «анализ → решения → архитектура → **фазы** → квалификация тестов → документация → коммиты».

**Проблема:** Слово «фазы» не раскрыто как «Phase 0, 1, 2, 3 из solution-architecture / плана реализации», не указано, что среди них есть **фаза с тестами** и её нельзя пропускать.

**Итог:** Исполнитель не получает явного триггера: «фазы берутся из плана реализации; не пропускать фазу с тестами».

---

### 1.4. run-analysis.md не напоминает о полном цикле

**Где:** run-analysis.md: «используй методологию и мышление @analysis.mdc».

**Проблема:** Команда не напоминает о последующих этапах процесса (решения → архитектура → план реализации → **фазы, включая тесты** → квалификация). При использовании run-analysis нет контекста «далее обязательны фаза тестов и квалификация».

**Итог:** Нет напоминания «после анализа идёт полный цикл, в т.ч. фаза с тестами».

---

### 1.5. run-phase не требует проверки «остались ли фазы по плану»

**Где:** run-phase.md: выполнение **одной** фазы N, ретроспективы, буфер уроков.

**Проблема:** Нет инструкции после завершения фазы N проверить: «в плане реализации есть ли следующая фаза (в т.ч. Phase 2 — тесты)? Не считать этап 5 завершённым, пока не выполнены все запланированные фазы».

**Итог:** После Phase 1 естественно остановиться; явной проверки «следующая фаза — тесты» нет.

---

### 1.6. Памятка: «тесты» как проверка, а не как фаза

**Где:** task-execution-process.md, п. 8 памятки: «Тесты — проверка по **test-qualification**; отчёт в папку таска».

**Проблема:** Формулировка звучит как «проверка **уже написанных** тестов», а не «сначала выполнить **фазу с тестами** (Phase 2 из плана), затем квалификация». Связь «фаза тестов в плане → выполнить в этапе 5 → затем этап 7» в памятке не отражена.

**Итог:** Исполнитель может не связать пункт «тесты» с обязательной Phase 2 из плана реализации.

---

## 2. Сводка причин

| № | Причина | Документ |
|---|---------|----------|
| 1 | «Одна фаза за раз» без требования не пропускать фазу с тестами и без перечисления всех фаз плана | run-task.md |
| 2 | Этап 5 (фазы) и этап 7 (квалификация) не связаны явно с «фаза тестов обязательна в рамках этапа 5» | task-execution-process.md |
| 3 | В run-task «фазы» не раскрыты как Phase 0,1,2,3 и не указано, что фаза тестов обязательна | run-task.md |
| 4 | run-analysis не напоминает о полном цикле и об обязательности фазы тестов | run-analysis.md |
| 5 | run-phase не требует проверки «есть ли следующая фаза (тесты) по плану» | run-phase.md |
| 6 | В памятке «тесты» = проверка, а не «сначала фаза с тестами» | task-execution-process.md |

---

## 3. Рекомендуемые изменения методики

Чтобы фаза с тестами не пропускалась:

1. **task-execution-process.md:** В этапе 5 явно указать: «Реализация по фазам включает **все** фазы из плана реализации (0, 1, 2, …). **Не считать этап 5 завершённым, пока не выполнена фаза с тестами** (если она есть в плане). Затем этап 7 — квалификация созданного/изменённого набора тестов.» В памятке уточнить: «Если в плане есть фаза тестов (напр. Phase 2) — выполнить её в рамках этапа 5; затем квалификация (этап 7).»

2. **run-task.md:** В перечислении этапов раскрыть: «фазы (Phase 0, 1, 2, … по плану реализации; **не пропускать фазу с тестами**) → квалификация тестов». Добавить правило: «Перед завершением блока «реализация по фазам» проверить по плану реализации: все ли фазы выполнены, в т.ч. фаза с добавлением/изменением тестов.»

3. **run-phase.md:** В конце добавить контрольную точку: «После завершения фазы N: если в плане реализации есть следующая фаза (напр. Phase N+1 — тесты) — не считать этап «реализация по фазам» завершённым; следующая итерация — фаза N+1.»

4. **run-analysis.md:** Кратко напомнить о процессе: «После анализа по процессу следуют: решения → архитектура → план реализации → **реализация по фазам (все фазы плана, включая фазу с тестами)** → квалификация тестов → документация → коммиты.»

После внесения этих правок исполнитель будет явно ориентирован на выполнение фазы с тестами и на связь этапов 5 и 7.
