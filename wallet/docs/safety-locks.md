# Уязвимости безопасности WebApp Amanita

## 🔴 Критические уязвимости

### 1. Base64 "шифрование" сид-фразы
**Описание:** Использование `btoa()` для "шифрования" сид-фразы и PIN-кода
**Местоположение:** `main.js:721` - `const encrypted = btoa(\`\${mnemonic}::\${pin}\`);`
**Риск:** КРИТИЧЕСКИЙ - данные легко декодируются через `atob()`

**Варианты решения:**
- **AES-GCM шифрование** с Web Crypto API
- **PBKDF2** для деривации ключа из PIN
- **Соль и IV** для каждого шифрования
- **Crypto-js библиотека** как альтернатива Web Crypto API

### 2. Слабый PIN-код
**Описание:** 5-значный PIN (100,000 комбинаций)
**Местоположение:** `main.js:826` - проверка длины PIN
**Риск:** ВЫСОКИЙ - легко подбирается брутфорсом

**Варианты решения:**
- **Увеличить до 6-8 цифр** (1M-100M комбинаций)
- **Добавить буквы/символы** в PIN
- **Защита от брутфорса** (задержки, блокировка)
- **Биометрическая аутентификация** (если доступна)

## 🟡 Высокие риски

### 3. Отсутствие защиты от брутфорса
**Описание:** Нет ограничений на количество попыток ввода PIN
**Местоположение:** `main.js:895-1000` - функция `processPinEntry`
**Риск:** ВЫСОКИЙ - неограниченные попытки подбора

**Варианты решения:**
- **Счетчик неудачных попыток** в localStorage
- **Экспоненциальные задержки** между попытками
- **Временная блокировка** после N неудачных попыток
- **Дополнительная аутентификация** (капча, биометрия)

### 4. XSS уязвимости
**Описание:** Потенциальные векторы для внедрения вредоносного кода
**Местоположение:** Весь код, особенно обработка пользовательского ввода
**Риск:** ВЫСОКИЙ - компрометация localStorage и перехват PIN

**Варианты решения:**
- **Content Security Policy (CSP)** заголовки
- **Санитаризация всех входных данных**
- **Использование textContent вместо innerHTML**
- **Валидация и экранирование** пользовательского контента

### 5. Небезопасное хранение в localStorage
**Описание:** Данные доступны любому скрипту на домене
**Местоположение:** `main.js:723` - `localStorage.setItem("seedEncrypted", encrypted)`
**Риск:** ВЫСОКИЙ - доступ через XSS или вредоносные расширения

**Варианты решения:**
- **SessionStorage** вместо localStorage
- **IndexedDB с шифрованием**
- **Web Workers** для изоляции криптографических операций
- **Периодическая очистка** данных

## 🟠 Средние риски

### 6. Отсутствие проверки целостности данных
**Описание:** Нет валидации зашифрованных данных
**Местоположение:** `main.js:908` - `const [phrase, savedPin] = decoded.split("::")`
**Риск:** СРЕДНИЙ - возможны ошибки при повреждении данных

**Варианты решения:**
- **HMAC подписи** для проверки целостности
- **Версионирование** формата данных
- **Валидация структуры** после расшифровки
- **Резервные копии** в безопасном хранилище

### 7. Утечка данных через логи
**Описание:** Чувствительные данные могут попасть в консоль
**Местоположение:** `main.js:717` - логирование PIN
**Риск:** СРЕДНИЙ - утечка через dev tools

**Варианты решения:**
- **Маскирование чувствительных данных** в логах
- **Условное логирование** только в dev режиме
- **Удаление логов** в production сборке
- **Использование безопасных логгеров**

### 8. Отсутствие защиты от timing атак
**Описание:** Время выполнения операций может раскрыть информацию
**Местоположение:** `main.js:910` - сравнение PIN
**Риск:** СРЕДНИЙ - потенциальная утечка через timing

**Варианты решения:**
- **Константное время** для сравнения строк
- **Добавление случайных задержек**
- **Использование криптографических функций** сравнения

## 🔵 Низкие риски

### 9. Отсутствие защиты от replay атак
**Описание:** Нет защиты от повторного использования данных
**Местоположение:** Весь процесс аутентификации
**Риск:** НИЗКИЙ - для локального приложения

**Варианты решения:**
- **Nonce/timestamp** для операций
- **Одноразовые токены** для критических операций
- **Сессионные ключи** с ограниченным временем жизни

### 10. Недостаточная энтропия для генерации ключей
**Описание:** Зависимость от качества Math.random()
**Местоположение:** `main.js:407` - `ethers.Wallet.createRandom()`
**Риск:** НИЗКИЙ - ethers.js использует crypto.getRandomValues()

**Варианты решения:**
- **Проверка качества** генератора случайных чисел
- **Дополнительная энтропия** от пользователя
- **Валидация** сгенерированных ключей
