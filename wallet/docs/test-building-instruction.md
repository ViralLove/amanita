# Инструкция по созданию и отладке тестов

## 🎯 Назначение

Данная инструкция описывает процесс создания и отладки тестов на основе плана тестирования (например, из `@safety1.md`) с использованием существующей браузерной тестовой инфраструктуры.

## 🚀 Быстрый старт - Запуск браузерных тестов

### Шаг 1: Запуск локального сервера
```bash
# Перейдите в директорию wallet
cd /Users/eslinko/Development/Amanita/wallet

# Запустите локальный сервер
python3 -m http.server 8080

# Или используйте Python сервер с поддержкой .env
python3 local-server.py
```

### Шаг 2: Открытие тестов в браузере
```bash
# Откройте в браузере (замените 8080 на ваш порт)
http://localhost:8080/tests/html/safety1-p0-tests.html
```

### Шаг 3: Запуск тестов
- Нажмите **"🚀 Запустить все тесты"** для запуска всех тестов
- Или **"🔍 Запустить по одному"** для пошагового просмотра
- Или нажмите **"▶️ Запустить тест"** на отдельной карточке

### Шаг 4: Анализ результатов
- Смотрите прогресс в **"📊 Сводка результатов"**
- Нажмите **"📄 Скачать лог"** для детального лога теста
- Используйте **"📄 Экспорт результатов"** для общего отчета

### Шаг 5: Отладка проблемных тестов
- Если тест падает, нажмите **"🔍 Детальный лог"** на карточке
- Проверьте консоль браузера (F12) для дополнительных ошибок
- Используйте **"📋 Копировать лог"** для анализа в текстовом редакторе

### Шаг 2: Создание тестовых функций

#### 2.1 Структура тестовой функции
```javascript
async function test_function_name() {
    console.log("🧪 [test_function_name] Запуск теста");
    
    try {
        // 1. Подготовка тестовых данных
        console.log("🔍 [test_function_name] Подготовка данных...");
        
        // 2. Выполнение тестируемой функции
        console.log("🔍 [test_function_name] Выполнение функции...");
        const result = await functionToTest();
        
        // 3. Валидация результата
        console.log("🔍 [test_function_name] Валидация результата...");
        if (result !== expectedValue) {
            throw new Error(`Ожидалось: ${expectedValue}, получено: ${result}`);
        }
        
        // 4. Проверка изменений состояния (если применимо)
        console.log("🔍 [test_function_name] Проверка состояния...");
        if (window.someVariable !== expectedState) {
            throw new Error(`Состояние не изменилось корректно`);
        }
        
        console.log("✅ [test_function_name] Тест пройден");
        return true;
        
    } catch (error) {
        console.error("❌ [test_function_name] Ошибка:", error.message);
        throw error;
    }
}
```

#### 2.2 Принципы создания тестов
- **Подробное логирование** с префиксом `[test_function_name]`
- **Валидация реального поведения** (не побочных эффектов)
- **Проверка изменений состояния** после выполнения
- **Обработка ошибок** с детальным логированием
- **Возврат boolean** результата (true/false)

## 🔧 Технические детали

### Синхронизация переменных
```javascript
// В main.js - экспорт переменных
window.currentPinInput = currentPinInput;
window.firstPinEntry = firstPinEntry;
window.pinStep = pinStep;

// В тестируемых функциях - чтение из глобальных
currentPinInput = window.currentPinInput || currentPinInput;
pinStep = window.pinStep || pinStep;
firstPinEntry = window.firstPinEntry || firstPinEntry;

// После изменений - обновление глобальных
window.pinStep = pinStep;
window.currentPinInput = currentPinInput;
```

### Graceful degradation для тестов
```javascript
// Обработка отсутствующих DOM элементов
function updatePinTitle(text) {
    const title = document.getElementById("pin-entry-title");
    if (title) {
        title.textContent = text;
    } else {
        console.warn(`⚠️ Элемент не найден (тестовая среда)`);
    }
}
```

### Интерцепция логов

## 📊 Критерии качества тестов

### Обязательные проверки (P0)
- ✅ **NO_FALSE_SUCCESSES** - Тесты не проходят при реальных ошибках
- ✅ **VALIDATE_REAL_FUNCTIONALITY** - Проверка реальной функциональности
- ✅ **NO_UNTESTED_CRITICAL_PATHS** - Все критические пути покрыты

### Важные проверки (P1)
- ✅ **CORRECT_LOGIC** - Валидные проверки, а не фиктивные условия
- ✅ **MINIMAL_MOCK_OVERUSE** - Минимальное использование моков

### Дополнительные проверки (P2)
- ✅ **DETAILED_LOGGING** - Подробное логирование для отладки
- ✅ **ERROR_HANDLING** - Корректная обработка ошибок
- ✅ **STATE_VALIDATION** - Проверка изменений состояния

## ⚠️ Типичные проблемы и решения

### Проблема: Тест проходит, но функция не работает
**Решение:** 
- Добавить валидацию реального поведения
- Проверить изменения состояния после выполнения
- Убедиться, что тест проверяет функциональность, а не побочные эффекты

### Проблема: Переменные не синхронизируются
**Решение:**
- Обеспечить двустороннюю синхронизацию между локальными и глобальными переменными
- Добавить чтение из window в начале функций
- Обновлять window после изменений локальных переменных

### Проблема: Логи не отображаются в тестах
**Решение:**
- Настроить интерцепцию console.log
- Добавить фильтрацию по ключевым словам
- Проверить правильность префиксов в логах

### Проблема: DOM ошибки в тестах
**Решение:**
- Добавить graceful degradation для работы в тестовой среде
- Проверять существование элементов перед обращением к ним
- Использовать console.warn вместо console.error для отсутствующих элементов
